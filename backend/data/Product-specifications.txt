PRODUCT SPECIFICATIONS
======================

Multi-Agent RAG System - Product Specification
-----------------------------------------------

Product Overview
The Multi-Agent RAG Demo is an intelligent document retrieval and question-answering system that combines multiple specialized AI agents with vector-based document search to provide accurate, grounded responses to user queries.

Core Features

1. Intelligent Agent Routing
   - Supervisor agent analyzes user queries
   - Routes to specialized agents based on query type
   - Supports retrieval, research, and direct response modes
   - Improves response accuracy through appropriate agent selection

2. Multi-Source Document Retrieval
   - Vector search across document collection
   - Semantic similarity matching
   - Metadata-based filtering
   - Fast retrieval (millisecond response times)

3. Iterative Research Capability
   - Multi-iteration search refinement
   - Configurable iteration limits (default: 3)
   - Synthesized findings from multiple searches
   - Progressive deepening of understanding

4. Conversation Memory
   - Multi-turn conversation support
   - Session-based history management
   - Checkpointing for state persistence
   - Thread isolation for concurrent users

5. User-Friendly Chat Interface
   - Real-time Streamlit UI
   - Clean message history display
   - Error handling with user-friendly messages
   - Chat history clear functionality

Technical Specifications

Frontend Specifications
- Framework: Streamlit 1.41.1
- Language: Python 3.12+
- Default Port: 8501
- HTTP Method: POST to backend /chat endpoint
- Message Format: JSON with "message" field

Backend Specifications
- Framework: FastAPI 0.141.1
- Language: Python 3.12+
- Default Port: 8000
- ASGI Server: Uvicorn 0.31.0+
- Graph Orchestration: LangGraph 1.2.11

Vector Database Specifications
- Provider: Pinecone
- Type: Serverless managed vector database
- Embedding Model: OpenAI text-embedding-3-small
- Embedding Dimension: 1536
- Distance Metric: Cosine similarity
- Chunk Size: 1000 tokens with 200-token overlap

LLM Provider Specifications
- Provider: OpenRouter
- Default Model: openrouter/auto
- Authentication: API key via OPENROUTER_API_KEY
- Embedding Endpoint: openrouter/text-embedding-3-small
- Temperature: Default (configurable per model)

API Specifications

Chat Endpoint
- URL: POST /chat
- Request Format:
  {
    "message": "string - user question or statement"
  }
- Response Format:
  {
    "response": "string - AI-generated answer",
    "status": "success|error"
  }
- Status Codes:
  - 200 OK: Successful response
  - 400 Bad Request: Empty message
  - 500 Server Error: API key missing or processing error

Health Endpoint
- URL: GET /health
- Response Format:
  {
    "status": "ok"
  }
- Purpose: Verify backend service is running

Agent Specifications

Supervisor Agent
- Role: Route incoming requests
- Inputs: User message, conversation history
- Outputs: Decision (retrieve/research/respond)
- Responsible for intelligent request routing

Retrieval Agent
- Role: Search document collection
- Inputs: User query or refined search query
- Outputs: Top-k relevant document chunks
- Default Retrieval: k=4 most relevant chunks

Research Agent
- Role: Iteratively refine search and findings
- Inputs: User query, previous findings
- Outputs: Synthesized research results
- Max Iterations: 3 (configurable via MAX_RESEARCH_ITERATIONS)

Response Agent
- Role: Generate final answer
- Inputs: Original query, retrieved context, research findings
- Outputs: Final answer response
- Ensures responses are grounded in retrieved documents

Performance Requirements

Response Time
- Health check: < 100ms
- Simple query response: < 2 seconds
- Retrieval query response: < 5 seconds
- Research query response: < 15 seconds

Scalability
- Support for concurrent users: 100+
- Document collection size: Up to 10,000 documents
- Chunk storage: Up to 100,000 chunks
- Daily message throughput: 50,000+ messages

System Requirements
- Memory: Minimum 4GB RAM per instance
- Storage: Depends on document size (Pinecone managed)
- Network: Stable internet connection for API calls
- Python: 3.12 or higher

User Interface Requirements

Chat Interface
- Display user messages on left
- Display assistant responses on right
- Show loading indicator during processing
- Display error messages in modal dialog
- Show timestamp for each message
- Provide clear visual distinction between message types

Sidebar Features
- Clear Chat History button
- Session information display
- Configuration options
- Status indicators

Configuration Requirements

Environment Variables (Backend)
- OPENROUTER_API_KEY: Required for LLM and embedding API calls
- CHAT_MODEL: Optional, defaults to openrouter/auto
- EMBEDDING_MODEL: Optional, defaults to openrouter/text-embedding-3-small
- MAX_RESEARCH_ITERATIONS: Optional, defaults to 3
- PINECONE_API_KEY: Required for vector database access
- PINECONE_INDEX_NAME: Optional, defaults to "rag-demo-index"

Environment Variables (Frontend)
- BACKEND_URL: URL of backend API, defaults to http://localhost:8000

Data Management

Document Storage
- Location: backend/data/ directory
- Supported Formats: .md, .txt files
- Automatic Processing: On backend startup
- Format: Text-based, human-readable

Chunk Processing
- Chunk Size: 1000 tokens
- Overlap: 200 tokens
- Metadata: Source filename, chunk index
- Embedding: Text-embedding-3-small (1536 dimensions)

Conversation History
- Storage: LangGraph MemorySaver (in-memory)
- Persistence: Per thread/session
- Isolation: Thread-based for concurrent users
- Retention: Until session cleared

Security Considerations

API Key Management
- Keys stored in .env files (not tracked in git)
- API key validation on backend startup
- Error handling for missing credentials
- Secure transmission via HTTPS/TLS

Data Protection
- Sensitive data not logged
- API request logging for audit
- Metadata filtering for privacy
- User session isolation

Deployment Considerations

Environment
- Development: Local localhost setup
- Production: Cloud deployment with proper scaling
- CORS Configuration: Allow frontend origin
- Rate Limiting: 100 requests/minute per user

Monitoring
- Health check endpoint monitoring
- Error logging and tracking
- Response time monitoring
- Resource usage monitoring
- Vector database availability
