POLICY: ENVIRONMENT AND SECRETS MANAGEMENT
=============================================

Policy ID: POL-SEC-009
Effective Date: 2026-03-15
Owner: Platform Engineering Team
Review Cycle: Semi-Annual

Purpose
-------
Standardizes how environment variables and secrets are configured across local, staging, and production environments for both the frontend and backend services.

Scope
-----
Applies to .env files, CI/CD secret stores, and any runtime configuration for the Streamlit frontend and FastAPI backend.

Policy Statements
------------------
1. Every environment variable required by a service must be documented in a corresponding .env.example file with a placeholder value, never a real secret.
2. Real .env files must never be committed to git; .gitignore must always exclude .env at both the frontend and backend level.
3. Production secrets are injected via the deployment platform's secret store, not baked into container images or source files.
4. The OPENROUTER_API_KEY and any Pinecone credentials must be treated as Critical-tier secrets requiring immediate rotation if leaked.
5. BACKEND_URL and other non-sensitive configuration may be set via plain environment variables without additional protection.
6. A secret scanning check should run in CI to catch accidental credential commits before merge.
7. Any accidental commit of a secret must trigger immediate rotation of that credential, even if the commit is later removed from history.

Enforcement
-----------
CI secret scanning failures block merges. Confirmed leaks are handled per the Incident Response Policy and require credential rotation within one hour of discovery.
